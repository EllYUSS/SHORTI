# Контекст проекта

Что выяснено по ходу работы и что осталось открытым. Этот файл существует,
чтобы знание не терялось вместе с сессией: переписка хранится локально на машине
и между компьютерами не переносится, а репозиторий — переносится.

## Открытые находки

Все проверены на текущем коде. Ни одна пока не исправлена.

**Экран «Обмен VIP и монет» недостижим.** Полная вёрстка на месте, заголовок,
состояние `promoCode`, обработка возврата — но `openAccountFlowPage("exchange")`
не вызывается нигде. Попасть на ввод промокода из интерфейса невозможно. Решить:
вернуть ссылку в профиль или удалить экран.

**Поисковый запрос протекает на главную.** `search` — общее состояние, и
`visibleShows` фильтрует по нему не только экран поиска, но и главную ленту.
Набрал запрос в «Поиске», ушёл на «Главную» — лента отфильтрована невидимым
запросом, поля поиска там нет, сбросить нечем. При уходе с экрана поиска
`setSearch("")` не вызывается.

**Тосты гасят друг друга.** Десять мест вида
`setToast(x); setTimeout(() => setToast(""), 1800)` без отмены предыдущего таймера.
Два сообщения подряд — и второе исчезнет раньше срока.

**Нижняя навигация видна на «Для вас».** `AGENTS.md` требует её там прятать,
класс `.for-you-navigation` её не скрывает, а только сдвигает на 10px. Либо
решение изменилось и не записано, либо регрессия.

**Мёртвый код.** Ветка `selectedCategory === "ANIME"` недостижима — в
`categoryTabs` только HOT, NEW и RANKING. Импорты `InfoCircledIcon` и
`ReloadIcon` не используются (`noUnusedLocals` в tsconfig не включён, поэтому
`tsc` их не ловит).

**Логотип ЮKassa загружается хотлинком** с `yookassa.ru`. Внешняя зависимость:
без интернета или при блокировке строка остаётся без логотипа. Положить файл
локально в `public/assets/`.

**Постеры весят 22 МБ.** PNG по 2–2,6 МБ при 1024×1536, девять штук грузятся на
главной одновременно. Просятся WebP или AVIF и ресайз под реальный размер
карточки. Плюс `public/assets/rewards/vip-diamond-chest.png` (2,1 МБ) не
используется нигде, но попадает в сборку.

**`design-qa.md` устарел.** Описывает табы «Награды / VIP-алмазы», иллюстрацию
сундука и историю алмазов — ничего этого в коде нет. Там же раздел про
полноэкранный режим помечен «visual confirmation on iPhone pending».

## Полноэкранный режим на iOS — что измерено на устройстве

Замерено на iPhone 14 Pro Max в Safari. Эти числа объясняют, почему расчёты
через `safe-area` и `vh` не работали.

| Величина | Значение |
|---|---|
| `innerHeight`, `visualViewport.height` | 775 |
| `100vh`, `100lvh` | 815 |
| `100svh`, `100dvh` | 775 |
| `env(safe-area-inset-top)` | **0** |
| `env(safe-area-inset-bottom)` | **0** |
| Экран устройства | 932 |

Выводы:

- **`safe-area` во вкладке Safari нулевые.** Страница под статус-бар не заходит —
  им распоряжается Safari. Любая логика на `env(safe-area-inset-*)` там холостая.
- **Странице отдаётся 815 из 932.** Остальные 117px (статус-бар плюс полоса
  Safari) недоступны никогда. Чёрная полоса снизу — это полоса браузера,
  подкрашенная цветом фона страницы у нижнего края.
- **`100lvh - 100dvh` = текущая высота панели браузера.** Чистым CSS, без JS и
  без событий, которые на iOS могут не сработать. Используется для отступа
  нижней навигации.
- **Полосы Safari во вкладке не убираются.** Fullscreen API на iOS для обычных
  элементов недоступен, а нижняя панель сворачивается только при скролле
  документа — которого нет, потому что приложение зафиксировано на всю высоту,
  а прокрутка идёт внутри него. Единственный способ — запуск с домашнего экрана.
- **Маскированные слои WebKit выкладывает поверх соседей, игнорируя `z-index`.**
  Из-за этого подложка шапки оказывалась над логотипом. Решение: подложка —
  отдельный элемент-сосед (`.header-scrim`), а не псевдоэлемент внутри шапки.
- **`transform: translateZ(0)` размывает текст на iOS.** Вынос на отдельный слой
  композитинга стоит резкости шрифта. Не использовать как средство управления
  порядком слоёв.

Общий вывод: геометрию полноэкранного режима проверять замерами на устройстве.
В эмуляторе все эти величины нулевые или совпадают, и ошибка не видна.

## Окружение

На Mac, где проект начинали, **нет системного Node и npm** — Homebrew содержит
только себя. Два Node внутри приложений (ChatGPT.app, Photoshop) подписаны с
library validation и не грузят сторонние нативные аддоны, а Vite 8 стоит на
rolldown, ядро которого — нативный `.node`. Рабочий бинарник там один:
`~/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node`,
его ставит Codex.

На обычной машине этой проблемы нет: `npm install && npm run dev`.

`.claude/launch.json` (конфиг превью-сервера) намеренно исключён из git —
в нём абсолютные пути к конкретной машине.
